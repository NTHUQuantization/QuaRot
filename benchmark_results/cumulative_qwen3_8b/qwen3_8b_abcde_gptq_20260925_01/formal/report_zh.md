# Qwen3-8B GPTQ A–E 指定分支比較：formal

96 題；每資料集 32 題；batch=1；greedy；thinking=false；自然 EOS；新增 token 上限 256；每題 3 sweeps。E=PARD2-TI，draft_k=15。

A=HIP（來源 branch main）；B=GEMM；C=Hadacore（GEMM+HadaCore）；D=Fusion；E=PARD2（TI）。五組共用 GPTQ W4A4KV4 checkpoint，grouped_h256_v1、activation clip=0.9。消融敘事順序：HIP → GEMM → Hadacore → Fusion → PARD2。B 保留 HIP 的 Hadamard 並加入 GEMM 優化；C 保留 B 的 GEMM 並加入 HadaCore。B/C 使用 2026-09-26 更新 commit，舊 pilot 已封存，不納入本報告。各組保留來源分支 kernel，僅適配 checkpoint 欄位與 cache API。

時間與 tokens/s 先取每題 3 次 median，再取跨題 median。P10/P90/P99 以每題 median 分布、線性插值計算；CSV 另列 pooled repeats 分布。P99 樣本少，只作描述，不能解讀為穩定服務尾延遲。

Peak memory 是 phase reset 後 PyTorch allocated／reserved 峰值，含常駐模型；不是整卡 VRAM。表列該資料集 E2E 最大 allocated 峰值，其他 phases 與 reserved 見 CSV。E2E 不含模型載入、tokenization 或網路。
